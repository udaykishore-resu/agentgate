00 — THE BRIEF

What the platform is actually for

Internal engineering teams build agents. The platform decides what those agents may reach, on what terms, and who pays.

An agent estate grows faster than any inventory of it. Teams ship agents onto AKS, EKS, Container Apps, VMs and Lambda; each one wants a model, a key and a budget. Left alone, the estate becomes a set of direct provider credentials nobody can revoke, spend nobody can attribute, and prompts nobody scanned.

AgentGate is the single path through. Every model call carries a verifiable workload identity, is admitted against a declared quota, is scanned on the way in and on the way out, is routed to a backend cleared for the data's classification, and emits a trace that ties consumption back to a named team and cost centre. Nothing about that is optional or opt-in — an agent that has not registered cannot obtain a token, and a token that does not name a promoted version does not pass authorization.

The constraint that shapes everything An external engineering team needs the gateway carrying production traffic early, and the interface published to them cannot change afterwards. That single sentence is why the wire contract is OpenAI-compatible and frozen at /v1, why every extension lives in x-agentgate-* headers rather than the body, and why the error catalogue and its HTTP status mapping are treated as an API surface rather than an implementation detail.

Three things, deliberately not split

The gateway sees every request but knows nothing about ownership. The registry knows ownership but sees no traffic. The observability plane sees telemetry but cannot compel anyone to emit it. Separated into three teams, each becomes plausible on its own and the join never happens. Held together, the telemetry is the promotion gate: an agent whose traces are incomplete cannot reach production, which is what converts instrumentation from a dashboard into a control.

01 — SYSTEM CONTEXT

Who talks to what

Three services, five classes of external system, four kinds of human with a stake in the outcome.

Fig. 01/System context/C4 level 1/agentgate v1

Agents obtain a token from the control plane, then send traffic to the gateway. The gateway never calls the control plane on the request path — only its cached JWKS. fleetview feeds promotion signals back to the control plane, which is the loop that makes telemetry enforceable.

Enterprise IdP

Workload identity federation

Issues the platform token an agent presents at exchange. AgentGate validates it against the platform issuer's own JWKS — it never mints the attestation itself.

Enterprise vault

Credential custody

Backs the SecretStore interface for provider keys and the fallback client-credentials path. No provider key ever reaches an agent.

ServiceNow

Change management

Holds the security-review reference the security_review gate requires for production, and receives the change payload a promotion generates.

CI system

Registration on deploy

Validates agent.yaml and registers the version. A manifest that fails here never reaches the promotion path at all.

Observability backends

Enterprise APM and Prometheus

Receive the same OTLP stream fleetview does, via the gateway-tier collector's fan-out — so the platform's own view and the enterprise view cannot silently diverge.

02 — RUNTIME TOPOLOGY

Three planes, different blast radii

The traffic plane must survive the trust plane being down. That is a deployment property, not a wish.

Fig. 02/Runtime topology/one region/traffic · trust · truth

The dotted edge is the only gateway → control-plane dependency, and it is a cached one. A control-plane outage stops new registrations and token exchanges; it does not stop traffic already holding valid tokens.

Traffic plane

Stateless, deadline-bounded

No local state that matters. Redis holds limits, quota reservations, the response cache and the jti replay set — and when Redis is unreachable the limiter degrades to per-replica in-memory enforcement rather than failing the request.

Trust plane

Small, audited, boring

Registration, credential issue and rotation, token exchange, promotion approval. Every state change writes an immutable record. Two-party approval is enforced in code, not in a process document.

Truth plane

Two-tier collection

A node-local agent tier absorbs bursts and adds resource attributes; an HA gateway tier does tail sampling and fan-out. fleetview computes completeness, orphan and attribution ratios and publishes them as gate signals.

03 — THE POLICY CHAIN

Sixteen stages, each named and timed

Every request runs the same ordered chain. Each stage emits its own duration, so “the gateway is slow” is always answerable with a stage name.

01trace.startContinue traceparent or begin a root span. Trace id is echoed in the response.
02authnVerify signature against cached JWKS; check iss, aud, exp, nbf; replay-check jti.
03authzVersion promoted for this environment, pool entitled, scope present.
04admissionSchema, body-size cap, parameter normalisation, context-window check.
05ratelimit.requestsRPM token bucket, one atomic Redis Lua call per request.
06quota.tokensEstimate, then reserve input + max_tokens. Settled against actuals at the end.
07guardrail.inputScan the prompt. Fail-closed on any pool cleared for restricted data.
08cache.lookupKeyed on the normalised request. Tool calls are never served from cache.
09transform.requestCanonical shape → provider dialect. OpenAI, Azure, Anthropic Messages, Bedrock, vLLM.
10routeFilter by data classification and residency, then select by weight, load and priority tier.
11invokeCall the backend under a circuit breaker, a retry budget and the caller's deadline.
12transform.responseProvider dialect → canonical shape. The caller never sees which family answered.
13guardrail.outputWindowed scanning over the completion; on a stream, ~256 tokens at a time.
14cache.storeOnly successful, tool-free, low-temperature responses within the pool's policy.
15meterSettle the reservation against actual usage; write the immutable usage record.
16trace.finishClose spans, attach gen_ai.* and agentgate.* attributes, export.
Identity & tracing Limits & accounting Content safety Routing & delivery
Why reserve-and-settle A token quota checked only after the fact is not a quota. The chain reserves the estimated input plus max_tokens before invoking, then settles the difference against the provider's reported usage — including a negative settlement when the estimate undershot, so the debt carries into the next window rather than evaporating. The whole reserve is one atomic Lua script, which is what makes it correct across replicas.

The overhead budget

Fifteen of the sixteen stages are ours; only invoke waits on somebody else. The latency SLI is written against exactly that split — agentgate.overhead_ms excludes provider time, because a latency objective that included it would measure the provider's health wearing the platform's name.

04 — SEQUENCE

Cold start: no secret exists anywhere

An agent pod starts with no credential. Federated workload identity is exchanged for a gateway token — RFC 8693, not a shared secret in an environment variable.

Fig. 03/Sequence/Token exchange and first request/cold JWKS

Client-credentials remains available for runtimes without federation, but it is recorded as attestation=client-credentials and one of the eight promotion gates refuses it — weaker attestation is visible rather than equivalent.

05 — SEQUENCE

Steady state: a unary completion

The common path, with the failover branch that makes multi-backend pools worth having.

Fig. 04/Sequence/Unary chat completion/cache miss · failover

The response names the backend that actually served it, and x-agentgate-failover-from names the one that did not. Consumers do not need it; on-call does, at 3 a.m., without opening a trace viewer.

06 — SEQUENCE

Streaming, where the status code is already gone

Once headers flush, every remaining decision must be made in-band. Output scanning has to work inside that constraint.

Fig. 05/Sequence/Streamed completion/windowed output scanning

Terminal frames — finish_reason and the usage block — are held back until the scanner has flushed, so a caller never receives a completion marker before the content it completes. Heartbeat comments keep intermediaries from timing out an idle window.

07 — IDENTITY & PROMOTION

Registration is a deployment step, not a ticket

CI registers the agent. Eight gates evaluate automatically. Two humans who are not the requester approve production.

An agent's identity is a URI — agent://<tenant>/<team>/<agent-name> — always qualified by version and environment. The registration record carries the owning team, on-call rotation, cost centre, data classification and requested quota; those fields are not documentation, they are the inputs to routing, chargeback and the gates.

Fig. 06/Flow/Registration to production/gate snapshot · two-party approval

The gate snapshot is immutable and records every gate result with the evidence values and evaluation timestamp. An approval references a snapshot, so “it passed when we checked” is a verifiable claim rather than a memory.

09 — OBSERVABILITY PLANE

Telemetry you can put weight on

A trace that is incomplete or misattributed is worse than no trace, because someone will act on it. The platform measures its own telemetry and publishes the result.

Spans carry OpenTelemetry gen_ai.* semantic conventions where they exist, plus an agentgate.* extension namespace for what they do not cover: the agent URI, version, environment, cost centre, pool, backend, cache outcome, guardrail decision, stage durations, TTFT and overhead. Content capture is off in production and redacted below it — the schema is designed so that no field carries prompt text by accident.

Four trust metrics

fleetview reconstructs traces from the collector stream and computes, per agent and environment: completeness (spans received against spans expected from gateway-side request counts), orphan ratio (spans whose parent never arrived), unattributed ratio (spans with no resolvable agent identity) and clock skew (child spans starting before their parents). These are not dashboard ornaments — telemetry_healthy reads the first one directly, and an agent below 95% cannot be promoted.

Fleet view

Every agent, one page

  • Agent, owner, on-call, version, environment
  • Health — SLI against the agent's own objective
  • Consumption — requests, tokens, spend to date
  • Chargeback identifiers — cost centre, tenant, team
  • Promotion state and last gate snapshot
Chargeback

Immutable usage records

One record per request: identity, model, backend, input and output tokens, unit price and its source, cache outcome, billable flag. Failed requests are recorded but not priced. Rollups are derived; the record is the ledger.

Cost control

Anomaly plus a hard ceiling

An EWMA detector flags a team's spend departing its own baseline, which catches a runaway loop within minutes. Behind it sits a hard daily ceiling per cost centre, because a detector is a warning and a ceiling is a limit.

11 — MIGRATION

Moving traffic without moving the contract

An existing service has consumers who integrated against its behaviour, including behaviour nobody documented. The migration assumes that.

Fig. 07/Flow/Strangler migration/frozen contract · reversible at every step

Shadow traffic is marked x-agentgate-shadow: true and excluded from every SLI denominator — mirrored requests serve no consumer, and counting them would let a migration quietly spend the production error budget.

The golden corpus is the artefact that makes the freeze real: recorded production requests with their recorded responses, replayed against both implementations on every build. A divergence is a build failure, not a discussion. Known, accepted divergences are enumerated explicitly — the repository currently carries eight, each with a written rationale — so “compatible” means a specific, reviewable list rather than a claim.

Discipline

Dependency posture

Three direct dependencies — JWT, UUID, Redis — vendored for offline reproducibility. OTLP export, Prometheus exposition, SigV4, event-stream decoding and YAML parsing are implemented against their specifications rather than pulled in, because in a regulated estate every transitive dependency is a supply-chain review somebody has to run.
